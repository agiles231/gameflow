# Authorized, resumable provider runs

Read effective Meshy settings in `.gameflow/tools/meshy.json` through meshy-config; read allowance/authority policy in `.gameflow/AUTOPILOT.md` or the policy it names. Project defaults are overridden by a selected recipe and then explicit task settings; validate against the actual Meshy MCP schema. Resolve allowed provider/account, permitted data/reference uploads, credit or spending ceiling and unit, allowed operations, per-run/job limits, and the applicable accounting window. Existing user authorization governs; ask only for a missing material allowance. Account balance alone is not project authorization.

Before submission:

1. Inspect the operation's actual schema and obtain a credible maximum charge for the requested settings, including any automatic variants or paid postprocessing. Use provider-reported estimates or current provider pricing when necessary. If charge bounds or remaining allowance cannot be established, pause that operation and record the missing decision; continue independent work.
2. Reconcile completed, outstanding, and uncertain requests with provider status and existing task evidence. The coordinator alone writes the allowance ledger in task evidence and serializes reservations across workers sharing an allowance. Workers request generation from the coordinator, which alone reserves and submits paid work and persists job/status/billing evidence; if a single coordinator cannot be ensured, do not run concurrent paid work.
3. Persist a reservation in durable task evidence before submission: task/asset ID, provider/account alias, operation/settings, accounting window, maximum reserved cost and unit, timestamp, and request/idempotency key if supported. Sum settled charges and all outstanding or uncertain reservations against the ceiling. Do not mix currencies or credits without an explicit policy conversion.
4. Submit once with the provider's idempotency field if one exists. Persist the returned job ID immediately. Poll using the supported read/status operation, within the task/run time budget. On interruption leave the reservation and resume from that job, rather than requesting another asset.

A timeout, transport error, lost response, or disconnected MCP can occur after billing. Treat such submissions as uncertain; retain the reservation and reconcile through request ID, job history, or provider support. Never retry a billable submission solely because no response arrived. A retry is safe only after nonacceptance is established or documented provider idempotency guarantees prevent duplicate charge. New variations are new billable work and require their own reservation.

Settle reservations from actual provider billing evidence; retain the conservative maximum when actual cost is unknown. Release a reservation only with evidence that it cannot be charged. A failed generation may still incur cost. When the allowance is exhausted, checkpoint the request and report the blocker; no alternate generation provider or local modeling fallback is allowed.

Submit and query generation exclusively through discovered Meshy MCP tools, never direct HTTP or UI. Future providers are inactive. Rigging/animation operations are deferred. Download to the task's designated staging directory. Check output type and successful decode/import before integrating it. Do not execute downloaded code or blindly copy provider metadata into scripts. Keep reference uploads within the permitted brief and data allowance.
