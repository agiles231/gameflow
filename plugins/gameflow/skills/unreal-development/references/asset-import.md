# Import delivered assets

Bind asset ID, authoritative original/source identity, integration/export artifact and destination package before import. Inspect existing references and use task-owned destinations for experiments. Existing accepted assets do not need regeneration under the Meshy policy.

All new complex meshes originate from Meshy MCP; local simple shapes require an explicit exception. Blender may provide noncreative integration adjustments only. Do not introduce creative mesh/material repair in Unreal as a workaround. Rigging and animation production and integration are deferred, including skeleton/clip import, retargeting and graph authoring.

Discover actual importer support. Record relevant format/version, units/axes/pivot, material slots and texture dependencies. Confirm that expected files are readable and import/load at the intended destination with supplied dependencies. Preserve original provider files and bind imported output identities to them. A tool success response alone is not proof of import.

Meshy acceptance is cheap delivery verification; do not add artistic, topology, anatomy, LOD-quality or numerical audits unless explicitly requested. Runtime integration changes still require the relevant gameplay/load tests, and cook/package checks when the task calls for them. Fix only necessary technical integration failures within scope, without creative repairs or unrequested regeneration.

Save owned packages and record warnings/errors needed to reproduce delivery failures. Do not globally save packages or overwrite unrelated accepted work.
